PRD: Frost Fitness V3 App Store Submission

Objective

Ship Frost Fitness V3 as a credible, App Store-acceptable release focused on AI-assisted meal logging and lightweight nutrition tracking.

This release intentionally removes the AI coach from the submitted app experience and narrows the product around a clearer utility: helping users estimate and track food intake from photos.

The goal is not to prove the full long-term Frost Fitness vision in this release. The goal is to get a coherent, useful app into the App Store with low review risk and enough product substance to avoid feeling like a thin AI demo.

Product Positioning

Frost Fitness V3 is a nutrition logging app that helps users quickly estimate and track calories and macros from meal photos.

It is not an AI coach, medical tool, diet prescription app, or personalized health advisor.

Recommended positioning language:

> Frost Fitness helps users log meals from photos, review estimated calories and macros, and track daily nutrition totals.

Avoid positioning language that implies medical reliability, prescriptive diet advice, or personalized health coaching.

Core User Job

> I want to quickly log what I ate, get a reasonable calorie and macro estimate, and track my daily intake without manually entering everything from scratch.

Target Release Strategy

V3 should be treated as a submission-focused release, not a broad product expansion.

Primary strategy:

  • Remove the AI coach from the submitted app experience.
  • Preserve AI image recognition for meal logging.
  • Make nutrition estimates editable and clearly labeled as estimates.
  • Add or preserve enough supporting utility to satisfy minimum functionality expectations: daily totals, meal history, and optionally a simple fasting timer.
  • Keep App Store metadata, screenshots, onboarding, and review notes aligned with the narrower product.

V3 Scope

1. Meal Photo Logging

User can take or upload a food photo and submit it for AI-assisted nutrition estimation.

The AI result should include estimated:

  • Food item name or names
  • Calories
  • Protein
  • Carbohydrates
  • Fat
  • Serving description, if available

The user can save the meal entry after reviewing the estimate.

2. Editable Estimates

The user can edit AI-generated meal data before or after saving.

Editable fields should include:

  • Food name
  • Calories
  • Protein
  • Carbohydrates
  • Fat
  • Serving description
  • Timestamp or meal time

The UI should make it obvious that AI nutrition output is an estimate, not a verified fact. Saved entries should reflect the user's edits, not preserve AI output as authoritative.

3. Daily Nutrition Summary

The app should show a simple daily nutrition view.

Minimum requirements:

  • Today's total calories
  • Today's total protein, carbohydrates, and fat
  • List of meals logged today
  • Empty state encouraging the user to add a meal
  • Totals update after adding, editing, or deleting meal entries

4. History

The user can view prior logged days and previously saved meals.

Minimum viable history is acceptable. A date list, simple day selector, or calendar-lite view is enough for this release.

The user should be able to:

  • Open previous meal entries
  • Edit previous meal entries
  • Delete previous meal entries
  • See day-level nutrition totals for prior days

5. Fasting Timer

Include the fasting timer if it is already implemented or low-effort to add cleanly. It helps the app feel more complete and gives users a reason to return without adding much App Store review risk.

Minimum requirements:

  • User can start a fast
  • User can stop a fast
  • User can select a target fasting window, such as 12, 14, 16, or 18 hours
  • App shows elapsed time and progress toward the selected target
  • App stores recent fasting sessions

Important constraint: do not frame fasting as medical advice or tell users what fasting duration they should choose.

Acceptable language:

> Choose a fasting target.

Avoid language like:

> You should fast for 16 hours to lose weight.

6. Privacy and Consent

Before first AI image analysis, show a clear consent screen or consent step.

The consent copy should explain:

  • Meal photos are processed using an AI service.
  • Photos are used to estimate nutrition information.
  • Estimates may be inaccurate.
  • The user can review and edit all results.
  • A privacy policy is available.

The implementation and App Store privacy disclosures must match the app's actual data behavior.

Arya/Jesse should confirm:

  • Whether meal photos are stored after analysis
  • Whether photos are stored locally, server-side, or by a third-party AI provider
  • Whether users can delete saved entries and associated images/data
  • Whether the privacy policy accurately describes the AI processing path

Removed or Deferred From V3 Submission

The following should not be visible or reachable in the submitted build:

  • AI coach or chatbot
  • Workout recommendations
  • Diet plans
  • Medical nutrition advice
  • Weight-loss prescriptions
  • Injury, diagnosis, treatment, supplement, or disease-related guidance
  • Personalized health recommendations based on medical conditions
  • Social features
  • Wearable integrations
  • Subscription or paywall, unless already implemented cleanly and not likely to complicate review

AI Coach Removal Requirements

Remove AI coach references from:

  • Submitted app binary, unless fully inaccessible to App Review
  • Navigation
  • Home screen modules
  • Onboarding
  • Settings
  • Empty states
  • Push notification copy
  • App Store screenshots
  • App Store description
  • App Review notes
  • Demo account flows

If the coach remains in code behind a feature flag, Arya should verify that App Review cannot access it through normal app use, deep links, remote config, stale state, or test account permissions.

App Store Review Strategy

The submitted build should present Frost Fitness as a utility app for logging meals and tracking estimated nutrition information.

The review posture should be boring and precise:

  • AI is used only for food photo recognition and nutrition estimation.
  • Nutrition values are estimates.
  • Users can review and edit all AI-generated data.
  • The app does not diagnose, treat, prescribe, or provide personalized coaching.
  • Fasting, if included, is a simple timer and history utility, not a recommendation engine.

Suggested App Review note:

> Frost Fitness helps users log meals from photos and track estimated calories/macros. This version does not provide medical diagnosis, treatment advice, diet prescriptions, or personalized health coaching. AI is used only to estimate nutrition information from user-submitted food photos. Users can review and edit all estimates before saving.

Key UX Requirements

  • Use "estimated" language anywhere AI-generated nutrition output appears.
  • Make editing obvious and easy.
  • Do not overstate AI accuracy.
  • Do not frame the fasting timer as health advice.
  • Keep the app utility-focused: camera/logging, daily totals, history, and fasting timer if included.
  • Avoid open-ended AI prompts or chat-style UI in the submitted experience.

Acceptance Criteria

  • User can complete first meal log from photo to saved entry.
  • User can edit AI-generated nutrition values before or after saving.
  • User can see daily calorie and macro totals update after adding, editing, or deleting meals.
  • User can view historical meal entries.
  • User can edit and delete historical meal entries.
  • User can start and stop a fasting session, if fasting is included in V3.
  • First-time AI photo use requires clear user consent.
  • No coach or chat UI is visible or reachable in the submitted build.
  • App metadata and screenshots describe only V3 functionality.
  • App Review notes accurately describe the submitted build.

Open Questions for Arya/Jesse

  • Is the AI coach currently compiled into the app, or can it be fully removed cleanly?
  • Are there any hidden entry points to the coach through navigation, deep links, remote config, or existing user state?
  • Where are meal photos stored, if anywhere, after analysis?
  • Which AI provider processes meal photos?
  • Do we already have a privacy policy URL ready for App Store submission?
  • Is fasting timer state local-only for V3, or synced with a backend/user account?
  • Is the current app already using subscriptions or payments in a way that would complicate review?

Implementation Recommendation

Jesse should implement this as a narrow V3 submission branch.

Recommended order:

  • Remove or fully gate the AI coach from the submitted app experience.
  • Audit all visible copy and metadata for coaching, medical, diet-prescriptive, or accuracy-overclaim language.
  • Confirm the meal photo logging path works end to end.
  • Ensure all AI estimates are editable.
  • Confirm daily totals and history work reliably.
  • Add or retain fasting timer only if it is clean and does not delay submission significantly.
  • Add first-use AI photo consent and privacy policy access.
  • Prepare App Store screenshots, description, privacy disclosures, and review notes that match the V3 scope.

Product judgment: V3 should feel useful, direct, and calm. The submission should not invite Apple to evaluate Frost Fitness as a health advisor. It should read as a meal logging utility with AI-assisted estimates.
