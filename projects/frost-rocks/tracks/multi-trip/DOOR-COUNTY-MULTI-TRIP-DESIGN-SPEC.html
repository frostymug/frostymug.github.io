Door County Multi-Trip — Final Design Spec

Izzy (Design) | 2026-08-01 | Status: FINAL DESIGN HANDOFF — ready for Arya feasibility and technical design. Product decisions approved by Andy, 2026-08-01.

1. The Door County job

Add the smallest trustworthy multi-trip slice for a second field trip. Andy must be able to capture Door County encounters without disturbing Finland, review either trip deliberately, see one continuous notebook history, use the correct offline field map, and export either the current trip or everything.

This is deliberately narrower than the durable Multi-Trip & Places Target Model. It does not build trip creation/end flows, Places, upcoming trips, capture without a trip, MapLibre, or the full temporal-lenses Review IA. Those remain later work.

2. Product decisions (locked)

3. Experience contract

3.1 Capture remains boringly safe

At capture time, Door County is visibly named in the notebook header and every new encounter writes to Door County. There is no choice to make, no remembered selection, and no way a Review visit can redirect the shutter to Finland.

The app may seed and select Door County during migration/setup, but that is implementation plumbing, not a user flow. Future lifecycle controls belong in Trips & Places.

3.2 Notebook is the shared field record

The Notebook is a single continuous reverse-chronological scroll across all encounters.

  • Door County encounters appear first while the trip is current.
  • Encounters from Finland appear below, separated by a labelled trip rule (for example, FINLAND 2026 · previous).
  • Existing within-day/event grouping remains intact inside each trip section.
  • Theme filtering operates across the whole timeline; empty/filter states must say whether no encounters exist at all or none match the chosen filter.
  • The notebook header identifies Door County 2026 as current but is not tappable as a trip chooser.

This is a historical reading surface, not a mechanism for changing the active capture context.

3.3 Review is the deliberate time-travel surface

The Review entry point opens with Door County selected. Its top header contains a tappable trip title and state label. Tapping it opens a quiet dropdown shelf with:

  • current trip: Door County 2026 · active;
  • prior trip(s): initially Finland 2026 · previous;
  • encounter/review-queue count where inexpensive to provide;
  • a checkmark on the selected review scope.

Choosing a shelf row reloads the review queue for that trip. It is a view/filter selection only:

  • it must not call the current-trip setter;
  • capture, map, notebook header, and Export Current Trip remain Door County;
  • direct links from a map pin or timeline encounter continue to open that encounter, regardless of the shelf’s prior selection.

The existing review reveal sequence and scheduling behavior do not change. The only change is which trip supplies a nav-initiated review queue.

3.4 Maps are a per-trip offline floor

The current trip’s map is Door County. Its static offline image and projection cover Green Bay to the southwest and Washington Island / Rock Island to the northeast. Pins outside that descriptor’s bounds remain unpinned, as today.

The map component must become descriptor-driven: image, dimensions, geographic bounds, label, and compact-card copy are inputs rather than Finland constants. The established Finland descriptor stays available for its trip; no global/world map is being implied.

The delivered Door County static field-map asset provides the raster, vector source, generator, calibrated bounds, and projection fixtures. Until that asset is bundled, an honest no-map state is preferable to rendering Finland for Door County.

3.5 Exports make scope explicit

The Export screen presents two actions before building:

  • Export current trip — Door County only; preserves the existing single-trip bundle format and is the field/WoZ handoff path.
  • Export all trips — all trip records, encounters, questions, photos, and relevant event data in one self-contained bundle.

Neither action silently changes the other’s scope. The result summary and bundle metadata must name the selected scope and included trip(s). Arya should choose the cleanest compatible all-trips manifest/journal representation; it must preserve each encounter’s trip identity and remain portable.

4. Required structural seams

The current repository is single-trip at origin/main (7f6c449): getOrCreateDefaultTrip() is used by app initialization, notebook, map, capture, review, and export; the map is Finland-specific; the database has a trips table but no current-trip state.

The implementation must introduce the following seams before adding the UI:

  • Current-trip accessor. A single persisted accessor returns the current trip. All capture, map, notebook-current-context, and current-trip export paths use it. getOrCreateDefaultTrip() may remain only as first-run Finland seeding/migration compatibility, not as an application-wide resolver.
  • Trip state. Persist at least active and previous now, using the durable vocabulary previous | active | upcoming; upcoming has no Door County UI or behavior. Backfill Finland as previous and seed/make Door County 2026 active/current.
  • Review scope. Review owns a local selected-trip scope. It is distinct from current trip and resets to current Door County on a fresh nav-initiated Review visit.
  • All-trip timeline query. Add a query/read model that returns encounters across trips in reverse chronology while retaining trip metadata for dividers. Do not fake this by merging client lists without a stable ordering rule.
  • Map descriptor. Replace FinlandMap/Finland-only projection constants with a generic field-map descriptor interface. The current trip resolves its descriptor through one registry/seam.
  • Export scope. Keep the existing current-trip builder intact where possible; add an explicit all-trips builder rather than treating “all” as an unlabelled current-trip export.

5. Migration and setup requirements

  • Use additive, versioned SQLite migrations.
  • Preserve the live Finland trip and every associated encounter, question, photo, keyword, and event reference.
  • Add current-trip persistence and trip state in the least risky form Arya recommends; the result must be unambiguous and testable.
  • In the same controlled setup, seed Door County 2026 and make it current/active; mark Finland previous. The setup must be idempotent so reinstall/re-run behavior does not produce duplicate Door County trips.
  • No change to encounters.trip_id NOT NULL in this release. Contexts/Places and unfiled capture are specifically deferred.

6. Scope boundaries

In scope

  • Behind-the-scenes Finland → Door County current-trip setup.
  • Review-only trip shelf for current and previous trips.
  • All-trip Notebook timeline with trip dividers.
  • Per-trip static map seam plus Door County field-map asset.
  • Current-trip and all-trips exports.
  • Tests, migrations, analytics/events needed to make the slice safe to field-use.

Out of scope

  • Trips & Places tab, trip creation, ending a trip, renaming, or user-facing current-trip selection.
  • Upcoming trip behavior, prep/T1, consolidation/T3, Places, home/unfiled capture.
  • MapLibre, online map data, or an all-trips world map.
  • A redesign of the review learning sequence.

7. Acceptance criteria

  • DC-MT-01 — capture safety: Every newly captured Door County encounter has the Door County trip id. Visiting Finland in Review cannot alter this.
  • DC-MT-02 — review scope: Review can switch between Door County and Finland from its header shelf; the selected queue and its empty state match that trip.
  • DC-MT-03 — timeline history: Notebook shows a single reverse-chronological history across Door County and Finland, with legible trip boundaries.
  • DC-MT-04 — map scope: Door County map is shown for current field use, covers the stated geography, and Finland’s static map still renders from its own descriptor.
  • DC-MT-05 — export clarity: Export Current Trip includes only Door County; Export All Trips includes both trip records with their associations and makes the scope clear in UI and output.
  • DC-MT-06 — migration safety: Existing Finland data survives upgrade unchanged and Door County setup is idempotent.
  • DC-MT-07 — field regression: camera-first capture, note enrichment/editing, questions, keywords, photo portability, and the existing export path remain functional offline.

8. Arya feasibility brief

Arya should recommend the minimal technical shape for current-trip persistence, state migration, cross-trip queries, descriptor registry, and all-trips export schema. The architectural choices are open; the experience contract above is not.

Flag any migration, TestFlight-data, offline-asset, or export-compatibility risk before Jesse begins implementation. PRs should be sequenced so data/setup and capture safety land before review/timeline/map/export UI, with regression coverage at each seam.

9. Provenance and supersession

This replaces the Door County decisions in MULTI-TRIP-P1-DOOR-COUNTY-DELTA-SPEC.md, whose Trips-tab and notebook-header-switcher portions are superseded. The durable target model remains the source for later Trips & Places, Places, and no-active-context work.
