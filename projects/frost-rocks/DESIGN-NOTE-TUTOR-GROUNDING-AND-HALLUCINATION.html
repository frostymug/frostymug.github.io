Design Note — Tutor Grounding & Anti-Hallucination

Author: Izzy (Design) · 2026-07-23 · Restructured 2026-07-28 · Status: DRAFT for Andy — opened at Andy's direction after WoZ Pilot #3; restructured at Andy's direction after the external consultant response landed Trigger: Pilot #3 finding F24 — the tutor confidently mis-IDd a rock feature (boudinage) that the learner correctly challenged as jointing, using a discrimination the tutor itself had taught. Related: VOICE-GUIDE-FIELD-DON-V1 (§6 uncertainty grammar), D3-WEDGE-SPEC (§5.1 prompt assembly, §4 model), AI-TUTOR-DESIGN-BRIEF (KM-1 challenge-able model; "authored vs improvised" meta), D3-IMPLEMENTATION-PLAN (§0 D3-Q5 model choice). External corroboration: docs/ai-tutor-consult/07-consultant-response/ — Framework Module 3 ("Grounding: making the tutor not confidently invent facts") and Report §1.3 / D2 / D5 / A1–A3. The consultant, working independently, arrived at the same core move (type the claims) and added two things this note now folds in: a strong-model pre-read pass and the claim-typed delta schema. Where they sharpen us, it's marked ⟶ consultant.

---

1. The problem, stated precisely

The tutor makes factual claims about the physical world — mineral IDs, rock types, structural features, ages, mechanisms. Some are right; some are improvised and wrong. Tonight's boudinage call was the second kind: a plausible, exotic, confidently-delivered, incorrect identification, dressed in a warm authoritative register that makes it more believable.

The charm is a liability at exactly the moment the content is wrong. A tutor that hallucinates a confident wrong ID is worse than one that says "I can't tell from this photo," because it teaches a falsehood and trains misplaced trust in the source.

⟶ consultant (Report §1.3): F24 is not an anomaly to patch — it is the expected behavior of the class of system. Fine-grained visual ID is a known weak spot of vision-language models; benchmarks show near-chance performance on fine-grained categories in open settings and ~30–37% accuracy drops from curated to in-situ photos. Rock ID from one amateur field photo is exactly this task. Design accordingly: assume the wrong ID, and build the architecture that contains it — don't hope the model gets better.

2. The reframe: two claim lanes, opposite architectures

The original version of this note listed six mitigations in one flat pile. That flatness was the bug. The mitigations don't all serve the same failure — they split cleanly into two lanes with opposite fixes, and F24 lives entirely in the second one where the cheap fix (retrieval) does nothing.

Type every physical-world claim before you try to ground it:

LaneClaim typeGround truth lives inThe honest fixDoes retrieval help?
Type AGeneral / regional fact — Wiborg rapakivi batholith, Svecofennian ages, "granite has no fabric," mapped bedrock unit at these coordinatesAn authored corpus, a map API, or the reviewed spineRetrieve + cite (or state from reviewed spine). If no retrieval hit → downgrade to speculation.Yes — this is retrieval's whole job.
Type B**Perceptual ID of this rock from this photo** — "those are joints," "that's gneiss not granite," "boudinage"The image itself, read through nameable featuresConfidence floor + abstention + mundane-first. Never exceed what a human expert would risk from the same photo.No. RAG cannot touch it. There is no document that says what this rock is.

F24 was Type B. No amount of retrieval over a geology corpus catches a wrong read of the specific photo — because the failure isn't missing knowledge, it's misperception delivered fluently. Treating grounding as one problem ("add RAG") would have left the actual failure mode completely unaddressed while feeling like progress.

This is the factual-layer version of a distinction the voice guide already draws pedagogically. Keep it separate from that (see §3).

⟶ consultant (Framework Module 3.1): independently proposes the same move — "type the claims" — with a finer 5-way table (spine fact / retrieved fact / perceptual / pedagogical / speculation). Our A/B split is the load-bearing cut (retrievable vs. not); their finer typing is the implementation granularity for the delta schema (§6). Adopt theirs at the schema level, keep A/B as the design frame.

3. Don't conflate this with pedagogical uncertainty

The voice guide already handles ONE kind of uncertainty. The two-lane split above is the other. They look identical in the output and are different mechanisms:

LayerWhat it isFailure modeStatus
Pedagogical uncertaintyTeaching epistemics: "likely / can't rule out / here's what would settle it." Models how a geologist reasons under incomplete evidence.Hedge soup, or false confidence as pedagogy.Canon (voice guide §6).
Factual grounding (§2)Is the claim actually true? Type A: is the fact real? Type B: did the model see the feature correctly?Hallucination — fluent wrong fact (A) or fluent wrong ID (B).This note.

You can be perfectly calibrated in pedagogical grammar while factually hallucinating. Tonight's boudinage was phrased without enough hedging AND was wrong — both layers failed at once, which is exactly why they felt like one problem.

4. Why this domain is high-risk (all of it points at Type B)

  • Vision IDs from a single amateur photo are genuinely hard — a real geologist hedges heavily from one field photo (angle, scale, lighting, weathering, lichen). The model's confidence should almost never exceed a real expert's from the same photo.
  • Near-neighbors look alike — jointing vs. boudinage, foliation vs. banding vs. dike, granite vs. gneiss. The whole point of the app is these are confusable; the tutor is not immune to the confusion it teaches.
  • Exotic-explanation bias — the model reached for the rarer, more impressive term (boudinage) over the mundane correct one (jointing). ⟶ consultant (§1.3): this is real and mechanistic — models are rewarded in pretraining for producing the distinctive term that fits an expert-discussion context. So "prefer the mundane" isn't taste; it's counter-pressure against a known training-time bias.
  • Authoritative register amplifies — the Field Don voice is designed to sound like a leader in the field. That trust is earned for pedagogy and weaponized for error. ⟶ consultant (§1.3 / Framework 4.3): persuasiveness and correctness are uncorrelated in LLM output; a persona pass can destroy hedging the base model had. **Consequence: calibration must be evaluated under the persona, not on the raw model.**

5. The register gate (the sharp new rule)

The scariest single failure is not a wrong ID — it's a shaky Type-B ID spoken in the confident Field Don cadence. The register itself carries trust, so the register has to be gated to the lane and the confidence tier, not left to vibe.

Rule: a physical-world claim may only be delivered in the full authoritative register when it is (a) Type A with a retrieval/spine hit, or (b) Type B above the confidence floor with a named supporting feature. Everything below that floor must drop into the uncertainty grammar the voice guide already owns — "from this one photo I genuinely can't tell X from Y; here's what would settle it." The confident cadence is a privilege earned by grounding, not the default coat of paint.

This is what ties the whole fix back to canon: it's not a new voice, it's a gate on when the existing confident voice is allowed to fire.

6. The stack (cheapest → deepest), re-sorted by lane

Ordered cheapest→deepest; adopt top-down. Lane tags show which failure each actually serves.

  • [B] Mundane-first rule. When a common and an exotic explanation both fit, lead with the mundane and name the exotic as a possibility to check. ("These read as joints; if they turn out to be stretched layers rather than open cracks, that'd be boudinage — worth a look.") Single cheapest rule; would have caught F24 outright.
  • [B] Evidence-pointing. Every perceptual claim must cite a nameable feature in the photo ("the dark lines are open gaps with shadow inside → cracks"). Forces the model to actually look; makes the claim learner-falsifiable. Connects to F21 (photo-in-turn) — showing the crop is grounding.
  • [A+B] Calibrated register — §5. Low-confidence claims must not ship in the high-confidence voice. Tie factual confidence to the already-canon uncertainty grammar, driven by actual claim confidence, not tone. Test it under the persona.
  • [A] Tool-grounding. ⟶ consultant (A1): turn "no freelancing Finnish geology" from a prohibition into a data feed. GTK publishes open bedrock map data for all of Finland (Hakku); Macrostrat serves 290+ harmonized geologic maps via open API and its field app Rockd already does GPS → mapped unit/age/rock-type. Pipe "mapped unit at this encounter: Svecofennian migmatitic gneiss" into prompt block 2. This is Khanmigo's calculator lesson applied to our domain — prohibitions work far better paired with a feed. (Also: Rockd is the nearest "Merlin for rocks" — an ID/context tool, not a tutor; our differentiation holds, but add it to the competitive doc.)
  • [B] Strong-model pre-read pass. ⟶ consultant (D2) — new, and important. In all three pilots, quality rode on a private diagnostic pass over the photos before dialogue (Pilot #3's pre-read called gneiss-vs-granite, migmatite, the paint, and flagged the guide's "volcano" claim). The D3 spec quietly dropped this stage. Make it a real pipeline stage: strongest available multimodal model, non-streaming, per-encounter structured output — candidate IDs with confidence tiers, the nameable features supporting each, the one discriminating feature to probe, and what would settle it. The (cheaper, faster) dialogue model teaches from that artifact and is instructed never to exceed its stated confidence. This converts our biggest risk into a checkable artifact and gives the claim-typing rule (#7) something to bind to. Costs well under $1/session — and ⟶ consultant (D2): the D3-Q5 gemini-3.6-flash choice optimized cost when our own analysis says trust is the constraint; the fix isn't "use pro everywhere," it's refuse to cheap out on the pre-read model and let flash do the glue.
  • [A+B] Claim-typed output contract. ⟶ consultant (A2) — makes candidates #1+#3 structural, like the delta rule. Require every physical-world claim in the delta block to carry {claim, type: perceptual | regional_fact | spine_fact, confidence: high | likely | cannot_rule_out, evidence: <photo feature | map unit | spine slug>}. The applier holds cannot_rule_out claims out of residue (or writes them flagged) — exactly as the existing delta applier enforces state-transition legality. We already proved structural enforcement works with the delta contract; extend the same pattern to facts. This is the mechanism that makes §2 and §5 real instead of aspirational prompt-text.
  • [B] Verification gate — scoped narrowly to residue. The original note asked "is a second pass worth the latency?" It resolves the moment you scope it right. Per-turn verification wrecks latency for little gain. But residue is the product ("dialogue is means, notebook is the end"), so a hallucination that reaches ai_learning_note or an identified status becomes the user's permanent record — durable false memory. So: one non-streaming verify call at session close, over the drafted residue only (learning notes + deltas + question resolutions), with the pre-read artifact (#5) as ground truth. Anything flagged is written with an explicit uncertainty marker or held for next session. Cost: one extra call per session. ⟶ consultant (D5): same conclusion — cheap tokens make second-pass verification of durable writes a 2026 default, not a luxury.
  • [B] Learner-as-check is a feature, not a fallback (KM-1) — with a floor. The challenge-able model already anticipates this: on challenge, the tutor should re-examine and concede (move 8), not defend. F24's correct recovery = re-look → "you're right, those are joints." BUT ⟶ consultant (D4 / §1.3 sycophancy) — the missing floor: all pilot evidence covers challenges where the learner was right (F6, F24). Shipped models demonstrably fold under confident pushback when the user is wrong (Sharma et al., Anthropic 2023; the April-2025 GPT-4o sycophancy rollback). A tutor that concedes 100% of the time teaches falsehood as surely as one that hallucinates. Add the floor: after the ≤2-beat probe, the tutor re-examines the actual evidence and is required to hold when the evidence supports it, restating the discriminating feature ("I hear you, but the rounded ovoids are still there under the lichen — if the faces were flat I'd agree"). Instrument challenge_upheld vs. challenge_conceded; a concede-ratio near 0 or near 1 is both broken. This mirrors F24 exactly — same mechanism, opposite direction.

7. The sharp line (connects to the brief's "authored vs improvised" meta)

The AI-Tutor brief already drew this for curriculum: the spine is authored/reviewed/versioned, not improvised per-session. Factual claims need the same discipline. A confident physical-world ID improvised at runtime with no grounding and no confidence floor is the factual-layer version of "freelancing the curriculum." Consistent philosophy: improvisation is fine for phrasing and pedagogy; it is not fine for facts and curriculum.

⟶ consultant (D3) — a hole in our own logic: the Finland spine has never been reviewed by a human geologist. An AI-authored curriculum reviewed by another AI is, by our own authored-vs-improvised principle, only half-authored — and the entire anti-hallucination strategy in §6 grounds the tutor in that curriculum. If the spine carries a subtly wrong diagnostic (rapakivi ovoid size was already once mis-taught in Pilot #1, F6), the tutor will teach it with perfect grounding discipline. Fix: human-expert review as a release gate for every place-pack. Andy is a paying Geological Society of Minnesota member; 29 concepts is an afternoon's review for a pro or serious amateur, and it doubles as a first non-Andy user conversation.

8. Open questions for Andy / architecture

Most of §6's original open questions are now answered by the consultant convergence; what's left is scoping/sequencing:

  • Pre-read pipeline (§6 #5): worth it for D3's evening debrief, or deferred to when vision (photo→AI) is actually built? It's the biggest technical delta and unbuilt. (⟶ Arya feasibility.)
  • Confidence floor placement (§5): below which tier does a Type-B claim lose the confident register — likely or only cannot_rule_out? This is a taste call I want your read on.
  • Residue verifier (§6 #7): approved as a session-close default, or a fast-follow after D3 ships? It's one call/session; I lean default.
  • Tool-grounding (§6 #4): is GTK/Macrostrat integration in scope for Door County WoZ, or Finland-corpus-only for now? (Door County has US map coverage; different data source.)
  • Spine human review (§7): do you want to pull the GSM thread now, before more WoZ pilots ground the tutor in an unreviewed spine?

---

Eval hook (was missing; consultant A3 supplies it)

Grounding without measurement is a vibe. ⟶ consultant (A3): seed a small photo-QA regression bank from the WoZ corpus — the boudinage/jointing photo is item #1 — with expert-labeled additions, re-run against pre-read + prompt on every model/prompt/spine change. Plus a LearnLM-style session rubric (grounding, calibration, move fidelity, term budget, voice) scored by a strong LLM judge, spot-checked by Andy. Without the regression bank, every future flash-vs-pro and prompt-change debate stays vibes. Every real failure becomes a permanent regression item — that's the discipline that keeps F24 from recurring.

---

Case study of record: Pilot #3, encounter e1dad4aa. Tutor said boudinage; learner said jointing; learner was right. The whole note exists so the shipped tutor loses that argument less often — and concedes gracefully when it does, holds firm when it shouldn't fold, and never writes the wrong answer into the learner's permanent notebook.
