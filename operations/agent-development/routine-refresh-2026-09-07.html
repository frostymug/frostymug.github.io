Agent Development Routine Refresh

Aspen | 2026-09-07 | Status: Draft for Andy review

Why the current system is stale

The fourteen live jobs are mechanically healthy, but the design now rewards repeated research summaries rather than changed behavior. Every agent receives the same two broad assignments, on a fixed cadence, with a Telegram message required after every run. The seed topics have become grooves, the archive proves activity rather than development, and Andy pays the notification cost whether or not a run produced anything useful.

The personal/professional split also creates an artificial distinction. The useful question is not which bucket an insight belongs in; it is whether the agent learned something from real work and changed its future behavior.

Proposed replacement: one monthly practice review per agent

Replace the two recurring jobs with one monthly, role-specific practice review for each live agent.

Each review must:

  • Inspect the agent's actual work since the previous review: artifacts, decisions, corrections, failures, user feedback, and handoffs.
  • Name one demonstrated strength to preserve and one recurring weakness or uncertainty to address.
  • Consult outside material only when it helps answer that specific weakness; do not perform a generic trend scan.
  • Choose one small behavioral experiment for the next month, with a concrete signal that will show whether it helped.
  • Revisit the prior experiment and mark it adopt, adapt, or drop.
  • Make at most one focused durable update to agent guidance or shared process. Proposed identity changes still require Andy's approval.
  • Notify Andy only when the run produces a proposed identity change, a process decision, a material risk, or a genuinely interesting question. Otherwise archive silently.

Quarterly personal calibration

Personal development should become a quarterly calibration inside the practice review, not a separate content-generation job. It asks whether the agent's voice, temperament, role boundaries, and relationship with Andy are becoming more distinct and useful. It must be grounded in interaction evidence, not another tour through the fictional character or archetype that inspired the agent's name.

Rotation and anti-staleness rules

  • Do not repeat a topic, source, or experiment from the previous three reviews unless new evidence justifies returning to it.
  • Prefer corrections, surprises, and near-misses over polished successes.
  • No file change is a valid outcome; manufacturing doctrine is not.
  • Each agent keeps a compact experiment ledger: date, evidence, experiment, signal, next verdict.
  • Aspen performs a quarterly portfolio review across agents to find duplicated learning, missing capabilities, and routines that should be retired.

Transition recommendation

Keep the existing jobs unchanged until Andy approves the replacement. Then disable all fourteen old jobs, create seven monthly practice-review jobs on staggered weeks, preserve the old archive as historical evidence, and run one agent manually as a pilot before enabling the other six.
